# 태그·속성 규칙

일관성이 곧 검색·필터·Dataview 쿼리의 힘입니다. 노트 종류별로 frontmatter(YAML 속성)와 태그를 아래로 통일합니다.

## 노트 종류(type)

| type | 위치 | 역할 |
|---|---|---|
| `역기획` | 10 역기획 | 게임 1개 분석 |
| `메커닉` | 20 메커닉 | 재사용 가능한 설계 부품 |
| `패턴` | 30 패턴·인사이트 | 게임을 가로지르는 발견·가설 |
| `MOC` | 90 MOC | 인덱스 |
| `가이드` | 00 시작하기 | 메타 문서 |
| `적용시트` | (프로젝트별 사본) | 특정 게임에 마스터 시트를 적용한 사본 |

## 역기획 노트 속성

```yaml
type: 역기획
game: ""          # 정식 게임명
developer: ""     # 개발사
release: 2020     # 출시 연도
genre: [시뮬레이션]
subgenre: []      # 콜로니심, 경영, 자동화, 샌드박스, 빌더, 타이쿤, 라이프심 등
platform: [Steam]
price_usd:        # 정가(USD)
status: 작성중    # 작성중 | 완료 | 보류
rating: 0         # 개인 평점 0~5 (참고용)
tags: [역기획]
```

## 메커닉 노트 속성

```yaml
type: 메커닉
category: ""      # 아래 카테고리 표 참고
maturity: 시드    # 시드 | 정리됨 | 확립
tags: [메커닉]
```

### 메커닉 카테고리(category)

시뮬레이션 게임을 분해할 때 반복되는 축입니다.

- `코어루프` — 분 단위 / 세션 단위 / 메타 단위 반복
- `경제` — 자원 소스·싱크, 화폐, 변환, 인플레이션 제어
- `진행` — 해금, 테크트리, 페이싱, 난이도 곡선
- `자동화` — 손작업 → 자동화 이행, 복잡도 관리
- `피드백루프` — 양/음 피드백, 창발(emergence)
- `공간·배치` — 그리드, 인접 보너스, 물류·동선
- `UX·정보설계` — 온보딩, 가독성, QoL, 정보 계층
- `리텐션·엔드게임` — 장기 동기, 목표 구조, 무한 모드

### 메커닉 노트 필수 구조 (증류) ★

메커닉 노트는 단순 설명이 아니라 **증류**(추상화)를 강제한다. 아래 세 섹션이 핵심이다.

1. **근본 원리** — 게임 불문, 이 메커닉이 *왜* 인간에게 먹히는가(심리·인지 버튼).
2. **설계 손잡이(Parameters)** — 설계자가 돌리는 변수와 양 끝이 만드는 경험 차이.
3. **게임별 손잡이 설정(비교표)** — 같은 손잡이를 게임들이 어떻게 다르게 맞췄나. *비교가 곧 인사이트다.*

"이 게임이 이렇게 했다"(서술)에서 멈추지 말고, "이 손잡이를 이렇게 돌리면 이런 느낌"(이식 가능한 원리)까지 갈 것. 템플릿은 `_템플릿/메커닉 템플릿` 참고.

## 패턴 노트 속성

```yaml
type: 패턴
confidence: 가설  # 가설 | 관찰됨 | 확신
tags: [패턴]
```

## 태그 규칙

- frontmatter `tags`에는 **종류 태그**만(`역기획`/`메커닉`/`패턴`/`가이드`/`MOC`).
- 본문 인라인 태그는 **주제**용으로 자유롭게: `#감정-만족감`, `#밸런스-인플레이션`, `#영감` 등.
- 띄어쓰기 대신 하이픈(`-`)을 씁니다. (Obsidian 태그는 공백 불가)

## 링크 규칙

- 메커닉은 **항상 링크**(`[[자동화 곡선]]`)로 부릅니다. 텍스트로만 쓰면 연결이 끊깁니다.
- 게임끼리 직접 비교할 땐 `[[게임A]] vs [[게임B]]`처럼 양쪽 다 링크.
- 노트명은 **명사형·단수·한국어 우선**(검색 일관성). 영문 원어는 본문 첫 줄에 병기.
