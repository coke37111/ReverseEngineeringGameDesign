# 사용 가이드

이 보관함은 **시뮬레이션 스팀게임을 역기획**하고, 게임 사이의 연결에서 인사이트를 얻기 위한 곳입니다.

> **정체성**: 이건 특정 게임 한 편을 위한 기획서가 *아니라*, 어떤 프로젝트에도 재사용하는 **게임 설계 지식 엔진**입니다. 사례(게임) → 부품(메커닉) → 원리(패턴)를 축적해 두고, 새 게임을 설계할 때마다 꺼내 씁니다. 특정 프로젝트에 적용할 땐 [[프로젝트 적용 시트 템플릿]]을 복사해 그 사본에서 결정합니다 — 지식 베이스 본체는 중립으로 유지합니다.

## 핵심 아이디어 — "메커닉을 공유 부품으로"

게임 하나하나를 따로 정리하면 지식이 섬처럼 흩어집니다. 이 보관함은 다르게 작동합니다.

1. 게임을 역기획할 때 그 게임이 쓰는 **메커닉을 `[[링크]]`로 연결**합니다. (예: `[[자원 변환 체인]]`, `[[자동화 곡선]]`)
2. 메커닉 노트는 자신을 링크한 게임들의 **백링크**를 자동으로 모읍니다.
3. → 한 메커닉을 누가 어떻게 변주했는지 한눈에 보이고, 그래프 뷰에서 **클러스터(=장르적 관성)와 다리(=교차 영감)** 가 드러납니다.

이게 인사이트의 원천입니다. "이 게임은 X를 어떻게 했나"가 아니라 **"X라는 문제를 여러 게임이 어떻게 다르게 풀었나"** 를 보게 됩니다.

## 폴더 구조

```
00 시작하기/      ← 가이드, 규칙 (지금 보는 곳)
10 역기획/        ← 게임별 역기획 노트 (작업의 본진)
20 메커닉/        ← 재사용 가능한 메커닉 원자 노트
30 패턴·인사이트/  ← 게임을 가로지르는 패턴, 발견, 가설
90 MOC/          ← 인덱스(지도) 노트 — 보관함의 목차
_템플릿/         ← 노트 생성용 템플릿 3종
_첨부/           ← 스크린샷, 다이어그램 등
```

## 작업 흐름 (새 게임 역기획)

1. `_템플릿/역기획 템플릿`을 복사해 `10 역기획/{게임명}` 으로 만듭니다.
2. 위에서 아래로 채우되, **다 채우려 하지 말 것** — 그 게임에서 인상적인 섹션만 깊게 파도 충분합니다.
3. 메커닉을 만날 때마다 `[[메커닉명]]`으로 링크합니다. 노트가 없으면 링크를 먼저 만들고(빨간/흐린 링크), 나중에 `20 메커닉`에 채웁니다.
4. 다 쓰면 `[[게임 MOC]]`에 한 줄 추가합니다.
5. 게임 3~5개가 쌓이면, 같은 메커닉을 비교해 `30 패턴·인사이트`에 발견을 적습니다. **여기가 진짜 산출물입니다.**

## 추천 Obsidian 설정

- **그래프 뷰**: 색상 그룹을 `tag:#역기획`(파랑), `tag:#메커닉`(초록), `tag:#패턴`(주황)으로 나누면 구조가 보입니다.
- **Templates 코어 플러그인** 켜고 폴더를 `_템플릿`으로 지정.
- (선택) **Dataview** 플러그인: MOC를 수동 목록 대신 쿼리로 자동 갱신할 수 있습니다. 쿼리 예시는 각 MOC 노트 하단에 주석으로 넣어 두었습니다.
