# 프로젝트 지침

> Cowork 프로젝트 설정의 Instructions에도 같은 내용을 넣어 둔다. 이 파일은 그 사본이자, 누가 보관함을 열어도 규칙을 알 수 있게 하는 단일 진실 원천이다.

## 정체성
이 프로젝트는 **"Reverse Engineering Game Design" — 게임 설계 지식 엔진**이다. 특정 게임 전용이 아니라 **어떤 프로젝트에도 재사용하는 중립 지식 베이스**다. 진입점은 [[홈]].

## 구조
- `10 역기획` — 게임별 분석 노트
- `20 메커닉` — 재사용 설계 부품 (증류됨)
- `30 패턴·인사이트` — 게임을 가로지르는 원리 (★ 진짜 산출물)
- `90 MOC` — 인덱스 ([[게임 MOC]] · [[메커닉 MOC]] · [[패턴·인사이트 MOC]] · [[설계 손잡이 마스터 시트]])
- `_템플릿` — 노트 생성 틀
- `40 프로젝트 적용` — 프로젝트별 적용 사본

## 원칙
- 흐름은 **사례(게임) → 부품(메커닉) → 원리(패턴)** 로 증류한다.
- 메커닉은 반드시 **근본 원리 + 설계 손잡이 + 게임별 비교표**로 증류한다. "이 게임이 이렇게 했다"(서술)에서 멈추지 말고 "이 손잡이를 이렇게 돌리면 이런 느낌"(이식 가능한 원리)까지 간다.
- **지식 베이스 본체(10/20/30/90)는 프로젝트 중립으로 유지**한다. 특정 게임 적용은 `40 프로젝트 적용`에 [[프로젝트 적용 시트 템플릿]] 사본으로 만든다.
- 게임 역기획은 **game-reverse-engineering 스킬**로 수행한다: 사실 검증 → 11섹션 노트 → 메커닉 증류 → MOC/백로그 갱신 → 링크 검증.
- 새 노트 작성 후 **위키링크 무결성**을 검증한다. 한글 파일명은 셸 마운트 지연으로 깨져 보일 수 있으니 Read로 재확인한다.
- 항상 **존댓말**.

## 레퍼런스 확장 기준
"성공작인가" 위에 **"이 게임은 어떤 손잡이를 남들과 다르게 돌렸나"**를 우선한다. 비교표에 새 값이 채워질 때 인사이트가 생긴다. 약한 축(예: 로그라이트 메타·도덕적 결단·절차 생성)을 극단으로 미는 게임을 우선 추가.
